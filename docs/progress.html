01总体判断

  • 两家在 Mac 上都用系统自带的 Seatbelt 沙箱，在系统层面限制文件和网络。
  • Codex 默认更紧，开箱接近要求；但默认能读全盘。
  • Claude Code 默认沙箱关闭，要自己配；配好后控制更细。
  • 设计逻辑相同，默认值不同：两家都是"没允许就不让做"。Codex 系统沙箱默认开、审批默认偏松；Claude Code 沙箱默认关、审批默认偏严。
  • 优先级两家一样：规则冲突时更严的赢（Claude：deny > ask > allow；Codex：forbidden > prompt > allow）；路径冲突时更具体的赢。
共同短板：在允许的文件夹里能改就能删，沙箱无法单独禁止删除。必须靠逐条审批，再加 git 或 Time Machine 备份兜底。
要求CodexClaude Code
只改指定文件夹默认需开沙箱
只读指定文件夹默认读全盘可挡住
不乱删审批 + 规则审批 + deny 规则
不乱上网命令断网 搜索需手动关需手动配置
不自装软件断网即可断网 + deny

02推荐配置

Codex：~/.codex/config.toml 
sandbox_mode    = "workspace-write"  # 只能写启动目录
approval_policy = "untrusted"        # 除安全只读命令外都要批准
web_search      = "disabled"         # 关掉联网搜索

[sandbox_workspace_write]
network_access = false
writable_roots = []
Codex：~/.codex/rules/safety.rules（预览功能） 
prefix_rule(pattern=["rm"], decision="forbidden", justification="禁止删除，请让用户手动删")
prefix_rule(pattern=["rmdir"], decision="forbidden")
prefix_rule(pattern=["curl"], decision="forbidden")
prefix_rule(pattern=["wget"], decision="forbidden")
prefix_rule(pattern=["brew"], decision="forbidden")
prefix_rule(pattern=[["pip","pip3","npm","pnpm","yarn"], "install"], decision="forbidden")
Claude Code：settings.json（最好放进 managed-settings.json） 
{
  "permissions": {
    "defaultMode": "default",
    "disableBypassPermissionsMode": "disable",
    "disableAutoMode": "disable",
    "blockReadsOutsideWorkingDirectories": true,
    "deny": [
      "WebFetch", "WebSearch",
      "Bash(rm *)", "Bash(rmdir *)", "Bash(unlink *)",
      "Bash(curl *)", "Bash(wget *)", "Bash(brew *)",
      "Bash(pip install *)", "Bash(pip3 install *)",
      "Bash(npm install *)", "Bash(npm i *)", "Bash(npx *)"
    ]
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "autoAllowBashIfSandboxed": false,
    "network": { "allowedDomains": [], "strictAllowlist": true }
  }
}
  • Codex 的规则只管终端命令，它自带的改文件工具仍可能删文件。
  • Claude Code 的 sandbox.enabled 不开，写文件和上网都不受系统限制。
  • autoAllowBashIfSandboxed: false 让每条改东西的命令都要你点同意。
  • WebFetch 必须禁止，它对部分文档网站默认免询问。
  • deny 规则能被 /bin/rm、bash -c 绕过；可靠的是"沙箱 + 逐条审批"。
  • 两边都别随便装 MCP 服务器或插件，它们不在沙箱里。

入口代码在哪跑能碰的文件

Claude 桌面 app本地或云端本地：所选文件夹
  • iPad 本身不运行代码，也读不到 iPad 里的文件（手动上传的除外）。
  • claude.ai 聊天：Settings → Capabilities 可关 "Allow network egress"。
  • claude.ai/code 网络四档：None / Trusted（默认）/ Full / Custom。选 None 也仍能连 Anthropic API。
  • Mac 上的设置文件对云端会话无效；云端要用仓库里的 .claude/settings.json 或环境变量。
  • Remote Control 可用 disableRemoteControl 关掉，或开启 Trusted Devices。

04Claude Code 设置文件优先级

managed › --settings › settings.local.json › .claude/settings.json › ~/.claude/settings.json
  • allow / deny 等列表是合并，不是覆盖。
  • 只有 managed 能防 AI 改设置：另外三个文件 Claude Code 自己会写（点"不再询问"就写进 local），managed 要 sudo 才能改。
  • 少数安全键在低层级设"更严格"的值也生效，如 blockReadsOutsideWorkingDirectories: true。

05Cowork 何时能读写 Mac 文件夹

2026-10-06 起 Pro / Max 的新任务都在云端执行。云端任务要碰本地文件夹，必须同时满足：

  1. 任务在 Mac 桌面 app 里发起（或桌面建的定时任务）
  2. 任务或项目连接了该文件夹
  3. 运行期间桌面 app 一直开着在线
  • 读写方式：桌面 app 把单个文件的副本送到云端处理，文件内容会经过 Anthropic 服务器。
  • 10/6 前开始的本地任务继续在本地跑完。
  • 带本地文件夹的项目只能在桌面 app 里用；其中新建的任务在云端执行，但仍可读写连接的文件夹。
  • iPad / 网页发起的任务永远碰不到本地文件夹。想让文件不出电脑，用 Claude Code 本地会话。

06云端结果怎么取回

Claude Code 云端会话

  • commit + push、开 PR，本地 git pull（最稳）
  • 发布成 Artifact，或让它把文件发进对话
  • 会话里的 Files 面板只能看，不能下载
  • VM 回收后，没 push 的东西就没了

claude.ai 聊天 / Cowork

对话里点 Download；iPad 上用系统预览打开，再"存储到文件"。

Codex 云任务

网页看 diff、Create PR、预览下载生成文件；本地用 codex apply <任务ID>。iPad 目前不能下载生成文件。

07云端会话会不会落到本地

  • 在 Mac 上打开、查看、指挥云端会话：不会本地化，也不碰本地文件。
  • 只有这些主动动作会落地：claude --teleport（拉分支并复制会话，之后是独立的本地会话）、Cowork 连接文件夹、codex apply。
  • 保守做法：云端任务里弹出"连接文件夹"时不点。
  • 在本地电脑打开本页无安全影响：它是浏览器隔离框架里的静态网页，碰不到本地文件、不下载任何东西；唯一外部请求是 Google 字体。
