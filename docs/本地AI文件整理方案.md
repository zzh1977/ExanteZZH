# 本地 AI 文件整理方案（Windows / 16GB 内存 / 完全断网）

## 一、结论先看

**先分流，再分别处理，每类文件用各自的模型：**

| 文件类型 | 怎么分出来 | 怎么处理 | 默认模型 |
|---|---|---|---|
| **中文文档** | 程序数汉字（不用模型） | 只单独分到 `中文文档` 文件夹，**不读内容、不改名** | 不用模型（可选：配 `qwen3:8b` 再细分） |
| **英文 / 德文文档** | 程序数英/德常用词（不用模型） | 模型读内容 → 分类、起名、写中文摘要 | **`llama3.1:8b`**（约 4.9GB） |
| **照片** | 按扩展名（jpg/png/heic…） | 看图模型看画面 → 分类、起名；读拍摄日期 | **`qwen3-vl:4b`**（约 3.3GB） |
| 音视频、安装包、压缩包、代码、相机 RAW | 按扩展名 | 直接归类，不用模型 | — |
| 认不出语言的文档（如扫描件） | 读不到文字、文件名也看不出 | 放到 `未识别语言` 文件夹，标记人工确认 | — |

工作方式：

```
待整理文件夹
   │ 第1步 分流（程序完成，不用模型，几乎瞬间）
   ├── 中文文档 ────────────────────────────> 中文文档\（原名不动）
   ├── 英文/德文文档 ──> llama3.1:8b 读内容 ──> 英文德文文档\合同协议\…  财务票据\…
   ├── 照片 ──────────> qwen3-vl:4b 看图 ───> 照片\风景旅行\…  证件卡片\…
   ├── 音视频/安装包/压缩包/代码 ────────────> 按扩展名归类
   └── 认不出语言 ──────────────────────────> 未识别语言\（人工处理）
   │ 第2步 按类别分批调用模型（同一模型的文件集中处理）
   ▼
计划表 plan.csv ──你用 Excel 检查/修改──> 执行整理 ──> 归档汇总表 + 撤销日志
```

全程只访问本机 `127.0.0.1`，不需要也不会联网。

> 各模型的特色、优缺点对比，以及“准确性 + 不丢文件”的保障机制，见 [本地模型选型对比.md](本地模型选型对比.md)。

### 为什么判断“是不是中文”不用模型

- 汉字和英文/德文字母是不同的字符，程序直接数一数就能 100% 分清，**比模型更准、更快**（每个文件不到 1 秒），也不会出现模型“看错”的情况。
- 程序会先看文件开头的一小段文字，读不到再看文件名。只看文件名不可靠：常有英文文件名的中文文件，或中文文件名的德文文件。
- 这一步只是“数字符”，**不会把内容交给任何模型，也不理解内容**。如果你希望完全只看文件名，把 `config.json` 里的 `language_detect` 改成 `"filename"`。

## 二、硬件评估（16GB 内存）

**三个模型不会同时运行**：工具先把所有文件分好流，然后一类一类地处理（先英德文、再中文、最后照片），同一时间内存里只有一个模型（安装脚本已设置 `OLLAMA_MAX_LOADED_MODELS=1`）。每次扫描最多切换 2–3 次模型，每次约 10–30 秒。

| 部分 | 占用 |
|---|---|
| Windows 系统 + 常用软件 | 约 4–6 GB |
| 正在运行的那个模型 | `llama3.1:8b` 约 6GB / `qwen3-vl:4b` 约 4–5GB / `qwen3:8b` 约 6–7GB |
| 剩余 | 约 3–6 GB，够用 |

硬盘：三个模型共约 13.4GB；只用英德文 + 照片两个模型约 8.2GB。

**速度参考**（纯 CPU、近几年的 i5/i7、R5/R7；有 NVIDIA 显卡会快 3–5 倍）：

| 文件 | 每个约 |
|---|---|
| 中文文档（只分流） | 不到 1 秒 |
| 英文/德文文档（`llama3.1:8b`） | 15–40 秒 |
| 照片（`qwen3-vl:4b`，已自动缩小到 1024 像素） | 15–45 秒 |
| 音视频/安装包等 | 不到 1 秒 |

照片多时最耗时间（1000 张约 5–12 小时），可以晚上挂机；工具支持**中断后接着跑**。如果照片只想按年份分、不需要按画面分类，把照片模型关掉即可（见第四节），速度会变成每张不到 1 秒。

## 三、离线部署步骤

因为目标电脑完全断网，需要先在一台**能上网的 Windows 电脑**上准备好安装包，用 U 盘拷过去。

> 这里是概要。**从下载到使用的逐步说明见 [操作手册.md](操作手册.md)。**

### 第 1 步：在联网电脑上准备（需下载约 14GB）

1. 下载两个安装程序，放进一个文件夹（如 `E:\offline_ai`）：
   - Ollama：<https://ollama.com/download> → `OllamaSetup.exe`
   - Python 3.14 64 位：<https://www.python.org/downloads/windows/> → 进入 3.14 的版本页，选 **Windows installer (64-bit)** → `python-3.14.x-amd64.exe`（不要选 Install Manager，它安装时要联网）
2. 在这台联网电脑上也安装好 Ollama 和**同一版本**的 Python（勾选 “Add python.exe to PATH”）。
3. 把本仓库下载到这台电脑，在 PowerShell 中运行：

   ```powershell
   cd 仓库目录\scripts
   powershell -ExecutionPolicy Bypass -File prepare_offline.ps1 -Out E:\offline_ai
   ```

   脚本会自动：下载 `llama3.1:8b`（英德文）、`qwen3-vl:4b`（照片）、`qwen3:8b`（中文细分，可选）→ 复制模型文件 → 下载 Python 依赖包 → 复制整理工具。

   > 中文只分流不细分的话，可以不带 `qwen3:8b`，省 5GB：`-Models llama3.1:8b,qwen3-vl:4b`

4. 完成后 `E:\offline_ai` 里应有：

   ```
   OllamaSetup.exe
   python-3.14.x-amd64.exe
   ollama_models\        ← 模型文件
   wheels\               ← Python 依赖包
   file_organizer\       ← 整理工具
   install_offline.ps1
   ```

5. 把整个文件夹拷到 U 盘。

### 第 2 步：在断网电脑上安装（约 15 分钟）

1. 双击安装 `OllamaSetup.exe`。
2. 双击安装 Python，**勾选 “Add python.exe to PATH”**。
3. 在 U 盘的 `offline_ai` 文件夹里打开 PowerShell，运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File install_offline.ps1 -Dest D:\AI
   ```

   脚本会：把模型复制到 `D:\AI\ollama_models`、设置 Ollama 的环境变量（只监听本机、一次只装一个模型）、创建工具专用的 Python 环境 `D:\AI\venv` 并离线安装依赖（系统 Python 不装任何包）。
   想额外用防火墙禁止 Ollama 联网：以管理员身份运行，并加参数 `-BlockFirewall`。

4. 右下角托盘图标里**退出 Ollama，再重新打开**（让环境变量生效）。

### 第 3 步：验证

```powershell
ollama list                      # 应能看到 llama3.1:8b、qwen3-vl:4b（和 qwen3:8b）
ollama run llama3.1:8b "Fasse in einem Satz zusammen: Das ist ein Test."
```

能正常回答就说明本地模型已可用。

### 手动安装方式（不想用脚本时）

- 模型：把联网电脑 `C:\Users\用户名\.ollama\models` 整个文件夹，复制到断网电脑同样位置即可。
- 依赖：联网电脑运行 `pip download -r requirements.txt -d wheels`，把 `wheels` 文件夹放到断网电脑 `D:\AI\wheels`，再运行 `D:\AI\file_organizer\setup_venv.bat`，它会建好 `D:\AI\venv` 并离线安装依赖。
- 也可以在 ModelScope / HuggingFace 下载 `.gguf` 模型文件，断网电脑上用 Modelfile 导入：
  ```
  # Modelfile 内容
  FROM D:\AI\Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf
  ```
  ```powershell
  ollama create llama3.1:8b -f Modelfile
  ```

## 四、使用整理工具

工具位置：`D:\AI\file_organizer\`，用 `.\organize.bat` 运行（它会自动使用工具专用的 Python 环境 `D:\AI\venv`）。**扫描阶段不会动任何文件**。

### 1. 扫描，生成整理计划

```powershell
cd D:\AI\file_organizer
.\organize.bat scan "D:\待整理" --out plan.csv
```

屏幕上会看到两步：先“分流”（很快），再“英文德文文档 N 个，模型 llama3.1:8b”、“照片 N 个，模型 qwen3-vl:4b”逐个处理。

常用选项：

| 想要 | 命令 |
|---|---|
| 中途关掉后接着跑 | 再运行同一条命令，已处理的自动跳过 |
| 中文文档也让 Qwen 细分（合同、发票、报告…） | 加 `--zh-model qwen3:8b`，或在 config.json 里设 `routes.zh.model` |
| 照片只按拍摄年份分（不用看图模型，很快） | 加 `--photo-model none` |
| 英德文换别的模型试试 | 加 `--en-de-model gemma3:12b`（需先导入该模型） |
| 完全不用模型，只分流 + 查重 | 加 `--no-llm` |

### 2. 用 Excel 打开 plan.csv 检查

| 列 | 含义 | 可以改吗 |
|---|---|---|
| action | `move` = 整理，`skip` = 不动 | 可以 |
| source | 原文件路径 | 不要改 |
| language | 中文 / 英文 / 德文 / 英/德 / 照片 / 未知 | 仅参考 |
| category | 目标文件夹，可多级，如 `英文德文文档/合同协议` | 可以 |
| new_name | 新文件名。中文文档保持原名；英德文和照片默认 `日期_标题.扩展名` | 可以 |
| summary / tags | 模型给的中文摘要和关键词 | 仅参考 |
| confidence | 把握：高/中/低；“规则”表示按扩展名、字符或关键词确定 | 仅参考 |
| note | 标“建议人工确认”的行请重点检查 | 仅参考 |
| duplicate_of | 内容完全相同的文件，默认 `skip` | 仅参考 |

改完直接保存（保持 CSV 格式）。

### 3. 先预览，再执行

```powershell
.\organize.bat apply plan.csv --target "D:\已整理" --dry-run   # 只打印，不动文件
.\organize.bat apply plan.csv --target "D:\已整理"             # 移动文件
.\organize.bat apply plan.csv --target "D:\已整理" --copy      # 复制（原文件保留，最保险）
```

整理结果：

```
D:\已整理\
  中文文档\季度会议纪要.docx                       ← 原名不动
  英文德文文档\合同协议\2024-03-01_Mietvertrag Wohnung.pdf
  英文德文文档\财务票据\2024-05-12_Invoice Office Supplies.pdf
  照片\风景旅行\2023-08-15_海边日落.jpg
  照片\证件卡片\2022-01-10_身份证正面.jpg
  音视频\会议录音.m4a
  未识别语言\scan_001.pdf
  _归档索引\归档汇总_20261025_103000.xlsx
```

同名文件会自动加 `(1)`、`(2)`，不会覆盖。

**防丢失**：同一磁盘直接改名；跨磁盘先复制、核对 SHA-256 指纹一致后才删除原文件。任何一步出错，原文件不动。执行完会对账：计划总数 = 已归档 + 跳过 + 失败。

**汇总归档**：目标目录下自动生成 `_归档索引` 文件夹：

- `归档汇总_日期时间.xlsx`：**汇总**页（按大类：中文文档/英文德文文档/照片…，再按细分类别，各多少个、多大）、**明细**页（语言、新旧位置、摘要、标签、指纹）、**未归档**页（跳过/失败原因）
- `归档清单_日期时间.csv`：本次明细
- `归档总索引.csv`：历次累计总表

### 4. 核对归档是否完好

```powershell
.\organize.bat verify "D:\已整理"     # 按累计总索引重新核对每个文件的指纹
```

会列出“不存在”或“内容已变”的文件。建议整理完、拷贝到移动硬盘后各核对一次。

### 5. 撤销

执行后会生成 `undo_日期_时间.csv`：

```powershell
.\organize.bat undo undo_20261025_103000.csv
```

### 6. 自定义（config.json）

- `routes`：三条处理线，每条可单独设置：
  - `folder`：放到哪个文件夹
  - `model`：用哪个模型，**留空 `""` 表示不用模型**（中文只分出来；照片按年份分；英德文只按语言分出）
  - `categories`：细分类别。英德文的类别后面写了英/德文含义，帮助模型理解，可以照样增删
- `language_detect`：`"content"`（看开头文字，默认，更准）或 `"filename"`（只看文件名）
- `photo_exts`：哪些扩展名算照片
- `ext_rules`：按扩展名直接分类的规则
- `keyword_rules`：文件名含某关键词就直接归入某类（优先于模型），中英德关键词都可以写，如 `"财务票据": ["发票", "invoice", "rechnung"]`
- `name_template`：命名格式，可用 `{date}` 和 `{title}`
- `max_chars`：每个文件读取多少字给模型看，越大越准、越慢（建议 1500–3000）
- `photo_max_side`：照片缩小到多少像素再给模型看（默认 1024，调小更快）

## 五、内存与速度优化

1. **一次只装一个模型**：安装脚本已设置 `OLLAMA_MAX_LOADED_MODELS=1`、`OLLAMA_NUM_PARALLEL=1`；工具也会把同一模型的文件集中处理。
2. **上下文不要开太大**：`num_ctx` 保持 4096；每增加一倍约多占 0.5–1GB。
3. **照片最费时**：不需要按画面分类就用 `--photo-model none`；或把 `photo_max_side` 调到 768。
4. **跑大批量时**关掉浏览器等占内存的软件，接通电源，电源模式设为“最佳性能”。
5. **分批处理**：按子文件夹分几次扫描，方便检查。

## 六、断网与数据安全

- Ollama 和整理工具都只连接 `127.0.0.1:11434`（本机），文件内容不出电脑。
- `OLLAMA_HOST=127.0.0.1` 确保不对局域网开放。
- 可选：`install_offline.ps1 -BlockFirewall` 给 Ollama 加防火墙出站拦截，双保险。
- 工具只做“移动/复制”，不删除文件；有撤销日志。第一次使用建议先用 `--copy` 或先拿一个小文件夹试。
- 重要资料整理前先备份。

## 八、常见问题

**Q：运行时报“连不上 Ollama”？**
A：确认右下角有 Ollama 图标；或在命令行运行 `ollama serve`。

**Q：报“本机缺少模型 …”？**
A：运行 `ollama list` 看实际名字；检查 `OLLAMA_MODELS` 路径是否指向复制过来的 `ollama_models` 文件夹，改完要重启 Ollama。也可以在 config.json 里把那条线的 `model` 改成已有模型，或留空不用模型。

**Q：中英混排的文件算哪种？**
A：按汉字和英文单词的比例算。以中文为主、夹杂英文术语的算中文；英文文件里只有几个中文人名、地址的算英文。

**Q：德文被认成英文（或反过来）？**
A：两者都交给同一个英德文模型处理，放在同一个 `英文德文文档` 文件夹里，只影响 language 列显示，不影响分类。

**Q：苹果手机的 HEIC 照片？**
A：已支持（依赖包里含 pillow-heif）。打不开的照片会按年份放好并标记人工确认。

**Q：电脑很卡 / 很慢？**
A：照片用 `--photo-model none`；把 `max_chars` 调到 1000；关闭其他软件。

**Q：分类不准？**
A：① 把 `categories` 改得更贴近你的实际文件；② 加关键词规则；③ 调大 `max_chars`；④ 在 plan.csv 中手动改，再执行。

**Q：plan.csv 用 Excel 打开是乱码？**
A：工具已用带 BOM 的 UTF-8 保存，一般不会乱码；若仍乱码，用 Excel “数据 → 从文本/CSV” 导入并选 UTF-8。

**Q：pip 离线安装失败？**
A：断网电脑上的 Python 版本必须和打包时一致（默认 3.14、64 位），因为部分依赖包与版本绑定。用了别的版本，就在联网电脑上加 `-PyVersion 3.13` 之类的参数重新打包。
