# 常见疑问：Python 环境、文件夹用途、命令含义

## 一、为什么不用 conda？

能用 conda，但这个场景下“官方 Python + 虚拟环境（venv）”更干净、更好维护：

| | 官方 Python + venv | conda（Anaconda / Miniconda） |
|---|---|---|
| 依赖数量 | 只需要 6 个包（读 PDF、Word、Excel、PPT、图片），都有现成的 Windows 安装包 | conda 擅长装很复杂的科学计算包（如显卡驱动相关的库），这里用不上 |
| 离线安装 | 一个文件夹的安装包加一条命令，已验证可行 | 离线建环境比较麻烦，要预先下好 conda 自己的包，或者用 conda-pack 打包整个环境 |
| 体积 | Python 约 30MB，依赖包约 20MB | Miniconda 起步约 100MB，Anaconda 好几 GB |
| 授权 | 免费 | Anaconda 默认软件源对 200 人以上的单位要收费；用 Miniforge 可以避免 |
| 隔离方式 | venv 是 Python 自带的功能 | conda 环境 |

### 让环境真正“干净”：用独立的虚拟环境

本方案已采用这种做法：**依赖装在独立的虚拟环境 `D:\AI\venv` 里，不装进系统 Python**。

- 所有依赖包都在 `D:\AI\venv` 这一个文件夹里，系统 Python 保持干净。
- 环境坏了，删掉这个文件夹，用 U 盘里的安装包一条命令重建，1 分钟左右。
- 版本已在 `requirements.txt` 里固定，每次重建的环境都一样。
- 运行时用 `.\organize.bat`，它自动使用 `D:\AI\venv`，不需要“激活”环境（PowerShell 默认禁止运行激活脚本，用 .bat 可以避开）。
- 重建环境：`.\setup_venv.bat`，它从 `D:\AI\wheels` 离线安装，约 1 分钟。

| 位置 | 内容 |
|---|---|
| 系统 Python | 只用来创建环境，不装任何包 |
| `D:\AI\venv\` | 工具专用环境，所有依赖包都在这里 |
| `D:\AI\wheels\` | 依赖包的离线安装文件，用来重建环境 |

> 维护方法（重建、查看、升级、卸载）见操作手册第七部分“Python 环境维护”。
> 如果偏好 conda，也可以改成 Miniforge + conda-pack 的离线方案，只是步骤会多一些。

## 二、三个文件夹是做什么的

### `file_organizer\`：整理工具本身

复制到断网电脑上，日常用的就是它。

| 文件 | 作用 |
|---|---|
| `organize.bat` | 运行入口：自动使用工具专用的 Python 环境 `..\venv` 运行 `organize.py`。日常用它，例如 `.\organize.bat scan …` |
| `setup_venv.bat` | 创建或重建工具专用的 Python 环境 `..\venv`：有 `..\wheels` 文件夹就离线安装，没有就联网下载 |
| `organize.py` | 主程序，有 4 个命令：`scan` 扫描并生成计划表，`apply` 执行整理，`verify` 核对归档，`undo` 撤销 |
| `config.json` | 设置：每类文件放哪个文件夹、用哪个模型、有哪些类别、关键词规则、命名格式等。用记事本修改 |
| `requirements.txt` | 需要的 Python 依赖包清单，版本已固定 |

### `scripts\`：安装用的两个脚本

只在安装时用一次。

| 文件 | 在哪台电脑运行 | 作用 |
|---|---|---|
| `prepare_offline.ps1` | 联网电脑 | 下载模型和依赖包，打成离线包 |
| `install_offline.ps1` | 断网电脑 | 把离线包装好：复制模型、工具和依赖包，设置 Ollama，调用 `setup_venv.bat` 建好 `D:\AI\venv` |

### `docs\`：说明文档

不影响运行。

| 文件 | 内容 |
|---|---|
| `操作手册.md` | 从下载到使用的 28 步 |
| `本地AI文件整理方案.md` | 整体方案：多模型分工、硬件评估、使用说明 |
| `本地模型选型对比.md` | 各模型优缺点、选择建议、防丢失机制 |
| `常见疑问.md` | 本文：Python 环境、文件夹用途、命令含义 |

仓库根目录的 `README.md` 是项目首页的简要说明。

## 三、打包命令是什么意思

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare_offline.ps1 -Out D:\offline_ai
```

| 部分 | 意思 |
|---|---|
| `powershell` | 启动 PowerShell 来执行后面的内容 |
| `-ExecutionPolicy Bypass` | Windows 默认禁止运行 .ps1 脚本文件。这个参数表示**只对这一次运行放行**，不会改动系统的安全设置，运行完就恢复原状 |
| `-File .\prepare_offline.ps1` | 要运行的脚本文件。`.\` 表示“当前文件夹里的”，所以要先在 `scripts` 文件夹里打开 PowerShell |
| `-Out D:\offline_ai` | 传给脚本的参数：离线包放到 `D:\offline_ai` |

这个脚本还接受两个参数：

- `-Models`：选择要下载的模型，例如 `-Models llama3.1:8b,qwen3-vl:4b`
- `-PyVersion`：断网电脑用的 Python 版本，默认 3.14

脚本运行时依次做 4 件事：

1. 用 Ollama 下载模型；
2. 把模型文件复制到 `D:\offline_ai\ollama_models`；
3. 下载 Python 依赖包到 `D:\offline_ai\wheels`；
4. 把 `file_organizer`、`docs` 和安装脚本复制进离线包。

断网电脑上的安装命令也是同样的写法：

```powershell
powershell -ExecutionPolicy Bypass -File .\install_offline.ps1 -Dest D:\AI
```

`-Dest D:\AI` 表示装到 `D:\AI`。它依次做 4 件事：

1. 复制模型到 `D:\AI\ollama_models`；
2. 复制整理工具、文档和依赖包到 `D:\AI\file_organizer`、`D:\AI\docs`、`D:\AI\wheels`（已改过的 `config.json` 会保留）；
3. 设置 Ollama：只允许本机访问、一次只装一个模型；
4. 运行 `setup_venv.bat`，创建 `D:\AI\venv` 并离线安装依赖包。
