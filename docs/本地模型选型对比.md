# 本地文件整理：大模型选型对比

适用条件：Windows、16GB 内存、完全断网，模型只做文件归类、命名、汇总归档。
（模型信息截至 2026 年 10 月。新模型的 Ollama 名称和大小以 Ollama 官网模型页为准，下载前请核对。）

---

## 一、先说结论

| 用途 | 推荐 | 理由 |
|---|---|---|
| **主力（准确度优先）** | **Qwen3.5-9B** 或 **Qwen3-8B** | 中文最好的一档，严格按 JSON 格式输出，16GB 能跑 |
| 速度优先 / 电脑较旧 | Qwen3.5-4B 或 Qwen3-4B | 体积约一半，速度约快一倍，准确度略降 |
| 扫描件、照片里的文字 | Qwen3.5（自带看图） 或 MiniCPM-V，另加离线 OCR | 普通文字模型看不懂图片 |
| 相似文件聚类、语义搜索（可选） | bge-m3 向量模型 | 不是聊天模型，专门算“两份文件像不像” |

**建议做法**：离线包里同时带上 `qwen3:8b` 和 `qwen3.5:9b`，拿 50–100 个自己的文件试点，两个模型各扫一遍，对比哪个分得准，再定主力（方法见第五节）。

**比选模型更重要的一点**：没有任何模型能保证 100% 分对。准确性和“不丢文件”靠的是**流程设计**，不是模型本身（见第四节）。

## 二、候选模型对比

### 推荐档（中文好、16GB 可流畅运行）

| 模型 | Ollama 名称 | 下载大小 | 特色 | 优点 | 缺点 |
|---|---|---|---|---|---|
| **Qwen3.5-9B**（阿里，2026.3） | `qwen3.5:9b` | 约 6.6GB | 新一代小模型，原生支持看图，上下文 256K | 中文理解、归纳能力在同尺寸中最强一档；能直接看图片/扫描件 | 较新，据第三方报道 Ollama 对其看图功能的支持还在完善，需较新版 Ollama 并实测；纯 CPU 比 8B 略慢；16GB 下需关掉其他大软件 |
| **Qwen3-8B**（阿里，2025） | `qwen3:8b` | 约 5.2GB | 成熟稳定的中文模型 | 中文好；结构化 JSON 输出稳定；Ollama 支持成熟、资料多；本方案默认模型 | 只能处理文字，看不了图片 |
| **Qwen3.5-4B** | `qwen3.5:4b` | 约 3.4GB | 小体积，也能看图 | 速度快、省内存；能看图 | 复杂、模糊文件的判断不如 9B |
| **Qwen3-4B** | `qwen3:4b` | 约 2.5GB | 最轻的可用中文模型 | 老电脑也能跑；速度最快 | 准确度在本表中最低 |

### 可选档（各有长处，但不作首选）

| 模型 | Ollama 名称 | 下载大小 | 优点 | 缺点 |
|---|---|---|---|---|
| **Gemma 4 E4B**（Google，2026.4） | `gemma4:e4b` | 约 9.6GB | 多模态（图片、音频），多语言，Apache 2.0 可商用 | 中文不如 Qwen；体积大，16GB 下偏吃力 |
| **Gemma 4 E2B** | `gemma4:e2b` | 约 7.2GB | 同上，更快 | 中文和准确度一般；下载体积仍不小 |
| **GLM-4-9B**（智谱） | `glm4:9b` | 约 5.5GB | 中文好，国产 | 2024 年模型，已被 Qwen3/3.5 超越；严格格式输出稍弱 |
| **MiniCPM-V**（面壁智能） | `minicpm-v` | 约 5.5GB | 中文看图、识别图片中的文字强，适合照片/扫描件 | 文字归类能力一般；建议只用于图片，文字文件仍交给 Qwen |
| **Phi-4-mini**（微软，3.8B） | `phi4-mini` | 约 2.5GB | 小巧、英文推理好 | 中文弱，中文文件不推荐 |
| **Llama 3.1-8B / 3.2-3B**（Meta） | `llama3.1:8b` / `llama3.2:3b` | 约 4.9 / 2.0GB | 生态成熟 | 以英文为主，中文文件名/内容理解差 |

### 不推荐

| 模型 | 原因 |
|---|---|
| DeepSeek-R1 蒸馏版 7B/8B | “深度思考”型，每次先写一大段推理，慢好几倍，输出格式不稳；文件归类用不上推理 |
| gpt-oss-20b（约 14GB）、Qwen3-30B-A3B（约 19GB）、Gemma 4 26B（约 18GB） | 16GB 内存装不下或极卡 |
| 14B 级（Qwen3-14B 约 9GB、Phi-4 约 9GB） | 能勉强跑，但系统会卡、速度慢一半以上，对归类准确度提升有限 |

### 辅助工具（不是聊天模型，但能提高准确度）

| 工具 | 作用 |
|---|---|
| **bge-m3**（`bge-m3`，约 1.2GB） | 向量模型：把内容相近的文件聚到一起、找“内容差不多”的近似重复、以后用自然语言搜文件 |
| **RapidOCR / PaddleOCR**（离线 OCR） | 扫描件、图片转文字。读字比大模型更准更快，而且不会“编”内容；转出文字后再交给 Qwen 归类 |

## 三、怎么选（按你的电脑）

| 情况 | 选择 |
|---|---|
| 有 NVIDIA 独显（8GB 显存以上） | `qwen3.5:9b` 主力；速度不成问题 |
| 只有 CPU，近几年的 i5/i7/R5/R7 | `qwen3:8b` 或 `qwen3.5:9b`，晚上挂机批量跑 |
| 老电脑 / 文件特别多 | `qwen3:4b` 先粗分，再对“建议人工确认”的文件用 8B 复扫 |
| 扫描件、拍照文件很多 | 先 OCR 转文字，或用 `qwen3.5` 看图；同时让 16GB 内存一次只加载一个模型 |

## 四、准确性与“绝不丢文件”：靠流程保证

本仓库的 `file_organizer/organize.py` 是按“**模型只提建议，程序负责搬运，人工最后确认**”设计的。

### 1. 提高归类准确性

| 措施 | 说明 |
|---|---|
| 类别固定 | 模型只能从 `config.json` 的类别列表里选（强制 JSON 格式 + 枚举），不会自己造新类别或乱写文件夹名 |
| 规则优先 | 图片/视频/安装包按扩展名分；文件名含“合同、发票、简历”等关键词按 `keyword_rules` 直接定类，规则优先于模型 |
| 稳定输出 | 温度设为 0、关闭“思考模式”，同一文件多次运行结果一致 |
| 自评把握 | 模型同时给出“高/中/低”把握；低把握、归到“其他”、读不到内容的文件，自动标“建议人工确认” |
| 人工把关 | 扫描只生成计划表，不动文件。你在 Excel 里看完、改完才执行 |
| 读内容而非只看文件名 | PDF / Word / Excel / PPT / 文本都会读取开头内容再判断 |

### 2. 绝不丢文件

| 环节 | 保护措施 |
|---|---|
| 扫描 | 只读，不动任何文件；扫描完核对“目录文件数 = 计划表行数”，漏了会提示 |
| 移动 | 同一磁盘：改名（瞬间完成，不会出现半个文件）。跨磁盘：先复制成临时文件 → **核对 SHA-256 指纹一致** → 改成正式名 → 最后才删除原文件 |
| 出错 | 任何一步失败，原文件保持不动，并记入“未归档”清单 |
| 同名 | 自动加 (1)(2)，绝不覆盖 |
| 重复文件 | 内容完全相同的只整理一份，其余标出来、默认不动，**不自动删除** |
| 删除 | 程序不会删除任何“唯一的一份”文件：移动时删原文件只发生在新位置校验一致之后；撤销复制模式时，只删除与原件完全一致的副本 |
| 对账 | 执行完显示：计划总数 = 已归档 + 跳过 + 失败，不平会报警 |
| 事后核对 | `verify` 命令按归档清单重新计算每个文件的指纹，查出丢失或被改动的文件 |
| 撤销 | 撤销日志可一键还原；复制模式下，副本被改过就不会删除它 |

### 3. 汇总归档（自动生成）

执行后，在目标目录的 `_归档索引` 文件夹里生成：

| 文件 | 内容 |
|---|---|
| `归档汇总_日期时间.xlsx` | **汇总**页：每个类别多少个文件、多大；**明细**页：每个文件的类别、新位置、原位置、摘要、标签、指纹；**未归档**页：跳过/失败的文件和原因 |
| `归档清单_日期时间.csv` | 本次归档明细（可用于 `verify`） |
| `归档总索引.csv` | 历次归档累计总表，以后找文件、核对都用它 |

## 五、试点评估：用自己的文件选模型

1. 挑 50–100 个有代表性的文件，复制到 `D:\试点`。
2. 两个模型各扫一遍：
   ```powershell
   python organize.py --model qwen3:8b   scan "D:\试点" --out plan_8b.csv
   python organize.py --model qwen3.5:9b scan "D:\试点" --out plan_9b.csv
   ```
3. 用 Excel 打开两张表，逐行看 category 列是否正确，数一下各自分对多少个，同时记下耗时。
4. 选分得准的做主力。若准确度接近，选更快的。
5. 发现某类文件总是分错：在 `config.json` 里加关键词规则，或把类别名称改得更明确（如把“资料”拆成“学习资料”和“产品资料”）。
